## Muse が引き継ぐ場合の改善点リスト(優先順)

1. **過去の公式版と突き合わせるとき、URL を正規化し、話題でも照合する。** URL は末尾の `/`・クエリ・`#` 以降を落としてから `cowork/cache/past_urls.txt` と比べる。さらに直近7日の `_posts/` を固有名詞(社名・製品名・CVE 番号)で検索し、同じ出来事が載っていたら採用しない。続報として載せるなら、要約の1文目に「何が新しいか」を書く

### 確かめたこと(Muse について公開情報から。出典は末尾)

- Muse は Meta のエージェントで、2026-09-08 ごろに公開。モデルは Muse Spark。クラウド上の自分のコンピュータ(Debian 系の Linux。ファイル・ターミナル・ブラウザ)で動き、アプリを閉じても予定やイベントに応じて作業を続ける
- 料金は Free(制限あり)、Power(月20ドル・週5億トークン)、Maximum(月100ドル・週30億トークン)と紹介されている(2026-09-16 時点の第三者のまとめ)
- 承認カードがあり、コネクタごとに「一部を確認」「常に確認」を選べる。承認は1回・タスク単位・継続のいずれかで与えられる
- 定期実行の信頼性は実証されていない。「定期実行が信頼できない」という利用者の投稿が1件ある(何がどの頻度で失敗したかは書かれていない。1人の感想)。第三者のまとめも「長期の完了率は確立していない」としている
- git や GitHub との連携は、公開情報では確認できなかった(今回のデモのコミットがどう作られたかは、本人か Muse に聞かないと分からない)

### 見立て: 移行で良くなること・失うこと

| 項目 | 今 | Muse に移すと | 手当て |
|---|---|---|---|
