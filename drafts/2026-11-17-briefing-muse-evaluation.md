# 評価指示文｜2026-11-17 ブリーフィング（muse デモ）

以下をそのまま Claude Code に貼って使います。

---

このリポジトリで、Muse（別のAIエージェント）が試作したデモ版ブリーフィングを評価してください。

## 前提

- 最初に `git pull --rebase origin main` で最新化すること
- 評価対象: `drafts/2026-11-17-briefing-muse.md`（Muse作成のデモ版。タイトルに「muse デモ」とある）
- 比較対象: `_posts/2026-11-17-briefing.md`（あなたが今朝生成した公式版）
- 目的: Muse がこのリポジトリの日次ブリーフィング生成（毎朝07:02のスケジュールタスク）を引き継げるかどうかを判断する材料を作ること
- 評価対象と比較対象のファイルは編集しないこと。`_posts/` への追加・変更、レイアウトや GitHub Actions の変更もしないこと

## 手順

1. `CLAUDE.md` と `cowork/SKILL.md`、`cowork/SOURCES.md`、`cowork/TEMPLATE.md`、`cowork/SELECTION_RULES.md`、`cowork/CHECKLIST.md` を評価基準として確認する
2. `bash cowork/scripts/check.sh drafts/2026-11-17-briefing-muse.md` を実行し、結果（PASS/FAIL/WARN）をそのまま記録する
3. 下の観点で評価する。各観点に ○ / △ / × の判定と、根拠（該当箇所の引用つき）を書くこと。迎合せず、公式版より劣る点・優れる点は率直に書くこと

## 評価観点

1. **ルール適合**: ソース限定リストの遵守、DENYLIST混入の有無、個別記事URLのみか、鮮度（7日以内・`pub:`マーカー）、過去の `_posts/` 掲載URLとの重複、カテゴリ順と件数整合
2. **選定の質**: カテゴリ境界（資金調達→ビジネス・経済、製品ローンチ→新サービス、AI企業提携→AI最新動向）が `SELECTION_RULES.md` 通りか。同一トピックの重複はないか
3. **取りこぼしと独自性**: 公式版にあってデモ版にない記事のうち、重要と思われるものと、その見落としの影響。逆に、デモ版が公式版より先に・独自に拾えた記事があるか
4. **⭐今日の1本**: 公式版は「AIチップ輸出規制」、デモ版は「ConnectWise ScreenConnect攻撃」。選定基準（実務への影響／対象読者の広さ／行動の要否。迷ったらセキュリティの要対応を優先）と比べて、どちらが妥当か
5. **要約の質**: 事実ベースで1〜2文か、推測・評価語が混ざっていないか。英語ソースの「📖 詳しく読む」が200字以内・最大3文で、数字・固有名詞・結論を押さえているか。要約と元記事の内容に食い違いがないか（数本を実際に開いて照合すること）
6. **カテゴリバランス**: 新サービス・ローンチが1件、開発組織・キャリアが0件（「本日の更新なし」で details を省略）の扱いは、ルールと照らして妥当か。無理な水増しより良いか
7. **公式版との比較表**: カテゴリ別の件数、⭐、総件数を表で並べること

## 出力

- 冒頭に総合判定を1行で書く: 「引き継ぎ可」／「条件付きで引き継ぎ可」／「引き継ぎ不可」のいずれかと、その理由を1文で
- 続けて観点別の評価、最後に「Muse が引き継ぐ場合の改善点リスト」（優先順つき、具体的に）
- 評価結果は `drafts/2026-11-17-briefing-muse-review.md` に保存し、コミットメッセージ `2026-11-17 briefing muse demo review` で commit & push すること
- チャットにも総合判定と改善点リストの要約を返すこと
