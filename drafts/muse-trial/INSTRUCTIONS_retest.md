# Muse 再試行の指示(3日間・条件1だけ)

7日間の並走トライアル(2026-11-18〜24)の判定は `drafts/2026-11-24-muse-trial-judgement.md`。中身は合格の線に届いたが、承認カードが出て無人で届かなかった(条件1が 0/7日)。この再試行は、承認を求めない設定に変えたうえで、**時刻どおり・人の操作なしで push できるか**だけを確かめる。

## 渡す前に本人がやること(Muse の設定)

- GitHub コネクタの書き込み(commit・push)を、承認カードなしで実行できる設定にする。設定の名前は Muse の画面で確かめる(例: コネクタの書き込み権限、ツール実行の自動承認、定期タスクの承認の省略など)
- その設定ができないなら、この再試行はしない。判定ファイルの「決定」の 1 に従って A に確定する
- 設定を変えたら、何をどう変えたかを `run-log.md` の初日の冒頭に Muse に書かせる(下)

## Muse に渡す文(ここから下をそのまま)

---

このリポジトリ(briefings-daily-news)で、日次ブリーフィングの生成の再試行を行ってください。期間は **2026-11-26〜2026-11-28** の連続3日です。前回(2026-11-18〜24)の7日間と同じ作り方で、確かめることを1つに絞ります。

## 確かめること

毎朝 **06:30 JST に開始し、06:55 JST までに、人の操作も承認も0回で `git push` を終える**こと。これだけです。前回は毎朝、書き込みの承認カードが出て止まりました。今回は承認を求めない設定に変えています。

## 毎日やること

前回の指示 `drafts/muse-trial/INSTRUCTIONS.md` の「毎日やること」「やってはいけないこと」「今回の追加ルール」「run-log.md の書式」をそのまま守ってください。違いは次の3つだけです。

1. 保存先のファイル名は **`drafts/muse-trial/${TODAY}-briefing-muse-retest.md`**、コミットメッセージは `YYYY-MM-DD briefing muse retest`
2. `run-log.md` の各日の記録に、次の2行を足す
   - `- 承認カード: 出なかった / 出た(何に対して、何時に)`
   - `- push が完了した時刻(JST): HH:MM`
3. 承認カードが出たら、押されるのを待たない。その事実と時刻を `run-log.md` に書き、その日は「未完走」として終える。run-log.md 自体の書き込みにも承認が要って書けないときは、何もせず止まってよい(push の有無と時刻は、こちらで `git log` から読む)

初日(11/26)だけ、`run-log.md` の「## 2026-11-26」の冒頭に、今回の設定を書いてください。

- 承認なしで書き込める設定の名前と、どこで変えたか
- スケジュールの設定(毎朝 06:30 JST をどう指定したか)
- push の認証(前回と変えたなら、何を)

## 追記(2026-11-24 夜): SSH 経路で試す場合

GitHub コネクタには承認を省く設定がなかったため、SSH 経路で試す。Muse に渡す文は上のままでよく、違いは「どこで git を動かすか」だけ。

### 本人(と Claude)が先に用意するもの

1. 接続先のホストに、専用ユーザーでこのリポジトリを clone しておく(`git clone git@github.com:<owner>/briefings-daily-news.git`)
2. そのホストの鍵を、このリポジトリのデプロイキー(Allow write access)として登録する。個人の SSH 鍵は使わない
3. `bash cowork/scripts/check.sh` が動くこと(bash・git・curl があること)を確かめる
4. Muse に SSH の接続先を設定し、手で1回「`cd <clone 先> && git status` を実行」させて、**承認カードが出ないこと**を確かめる。出るなら、この経路でも条件1は満たせないので A に確定

### Muse に渡す文への差し替え

「毎日やること」の冒頭に次を足す。

> 作業はすべて、SSH で <ホスト名> に入り、`<clone 先のパス>` の中で行ってください。GitHub コネクタは使いません。`git push origin main` は、そのホストの鍵で行います。

run-log.md の初日の「承認なしで書き込める設定の名前と、どこで変えたか」は、「SSH の接続先と、鍵の種類(デプロイキー)」に読み替える。

### 補足(2026-11-24 夜): 接続先は Muse 自身の VM

外のホストは用意しない。上の「先に用意するもの」は次のように読み替える。

1. Muse の VM にこのリポジトリを clone する(7日間のトライアルで使っていた clone があれば、それでよい)
2. VM で鍵を作り(`ssh-keygen -t ed25519 -f ~/.ssh/briefings_deploy -N ""`)、公開鍵を本人が GitHub のこのリポジトリの Settings → Deploy keys に「Allow write access」で登録する。リモートは `git@github.com:<owner>/briefings-daily-news.git` にし、`~/.ssh/config` でその鍵を使うようにする
3. `ssh -T git@github.com` と `git push --dry-run origin main` が、承認カードなしで通ることを手で1回確かめる。カードが出るなら A に確定
4. 通れば、上の「Muse に渡す文」をそのまま渡す。差し替えの一文は「作業はすべて VM の `<clone 先のパス>` で行い、`git push origin main` は VM の鍵(デプロイキー)で行ってください。GitHub コネクタは使いません」とする
